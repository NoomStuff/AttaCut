# Test audit

Reviewed on 2026-10-01. The recommended code and test changes are implemented. Local validation ran on Windows. The release workflow verifies packages on Windows, macOS and Linux.

## Checks worth keeping

The real-media suite earns its size. Format tests check presentation times, copied-frame hashes, boundary quality, stream counts and color metadata across codecs, including variable frame rates and open GOPs. PCM and AAC join tests cover different discontinuity risks. Metadata tests compare subtitle content and timing, chapters, attachments, rotation and HDR preview conversion.

Storage recovery, source ownership, seek cancellation, byte budgets and bounded-work checks protect actual failures. Renderer and schema defaults come from independent declarations, so their equality check prevents drift. Electron tests exercise preload, IPC, bundling, real decoding and input routing that unit tests cannot prove.

## False failures addressed

| Previous assumption                                                    | Current check                                                                                                                                                                                          |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Seeks finish within fixed 100 to 250 ms sleeps                         | Wait for decoded playback position, displayed clock and seeking completion. Frame stepping checks the expected frame time.                                                                             |
| Displayed time consists only of seconds                                | Parse hours, minutes and seconds.                                                                                                                                                                      |
| One cold seek including Playwright overhead must take less than 750 ms | Routine long-recording test bounds completion. An opt-in benchmark measures seven decoded seeks inside the renderer, reports the samples and checks the median against a configurable hardware target. |
| Fade-out must start before opacity reaches 0.95                        | Accept a completed fade-in, then require monotonic fade-out and eventual removal.                                                                                                                      |
| Playwright always observes a brief conflict-indicator leaving state    | Attach a mutation observer before triggering the transition and inspect its recorded states.                                                                                                           |
| Polling always catches a narrow natural-playback interval              | Record bounded playback history before playback. Final seeks and stop assertions still inspect current state.                                                                                          |
| Every supported format fits inside one shared 300-second test          | Each format has its own source/export playback test and 120-second budget. A manifest check prevents a missing fixture set from silently removing coverage.                                            |
| Every local checkout has bundled FFmpeg at one hardcoded path          | Shared environment/bundled/PATH resolution. Direct FFmpeg processes hide console windows.                                                                                                              |
| An existing format fixture still matches the current recipe            | Regenerate fixtures on every media run. This deliberately spends generation time to avoid stale recipes or tool versions.                                                                              |
| Everything left in work/formats is a suite fixture                     | Keyframe and playback tests use explicit source/output paths in the generated manifest. Cover pictures and experimental leftovers cannot enter the suite.                                              |
| Cancellation must happen after a fixed 100 or 150 ms delay             | Export and preview cancellation wait for real FFmpeg progress. Existing process tests verify termination, escalation and waiting for handle closure.                                                   |

The development work gate is absent from packaged apps. It pauses between export items, so the close tests prove lifecycle ordering and preservation rather than pretending to prove termination of an actively encoding child. Real FFmpeg cancellation and process handle-release checks cover that separately.

## Desktop interference

Routine app tests are invisible and mute device output without changing the app's own mute/volume state or exported audio. Windows/macOS use zero opacity, showInactive, no taskbar entry and ignored native mouse input. Linux uses a hidden, non-focusable window and immediately hides native show events, including GTK fullscreen transitions. Background throttling is disabled. A fully hidden Windows trial stalled paused video and animation rendering, so keeping the invisible native window rendering preserves the checks' effectiveness.

Second-instance opens do not raise a background test window. Background and fullscreen checks verify that presentation stays invisible and unfocused while decoded playback and document keyboard input work. ATTACUT_TEST_VISIBLE=1 enables visible debugging, still with muted device output.

The Windows packaged launcher smoke briefly shows a native window without requesting focus. It identifies and closes only its own launched runtime. The separate bun run test:native command explicitly runs the visible activation smoke. Routine test:ui, test:all and verify:release exclude that smoke.

Background tests do not prove speaker audibility or physical OS drag gestures. Menu routing and drop-path tests exercise their real app boundaries, while the visible Windows smoke covers actual keyboard/dialog/activation behavior. The existing package matrix runs routine checks on macOS and Linux. Their visible native activation smoke still needs a separate run. Audible quality remains a manual playback check.

## Validation

Windows verification passed after integrating main's 0.15.0 changes: formatting, lint, type checking, build, 188 unit tests, the complete real-media suite, 92 routine UI/playback tests, portable and installer packaging, the native launcher check and 10 packaged-app tests. Playwright needed no retries. The routine run skipped only the opt-in seek benchmark.

The Windows visible native smoke and controlled seek benchmark also passed in targeted runs. They remain separate from routine verification because one requests OS focus and the other measures hardware performance. Speaker audibility and macOS/Linux native activation remain manual or opt-in checks.

Release CI exposed a Linux GTK fullscreen show event after the Windows run. Background Linux windows now reject focus and re-hide that event while retaining the real fullscreen transition. The fullscreen check also requires decoded playback inside fullscreen and successful exit.

Intel macOS CI also exposed an encoder capability assumption. HDR10+ now uses a small authored fixture with its regeneration recipe, so the test checks detection and preservation policy without requiring optional HDR10+ encoding support.

Windows CI caught a decoder-held file handle during source removal. That test now releases the preview reader after creating its real export plan and waits for the external mutation before asserting refusal and recovery.
